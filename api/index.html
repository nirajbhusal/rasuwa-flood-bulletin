Endpoint

  • api/overview.ne.json — Nepali flattened (convenience)
  • api/overview.en.json — English flattened (convenience)

Canonical bulletin: https://nirajbhusal.github.io/rasuwa-flood-bulletin/

CORS / caching

GitHub Pages serves these as static GET files. Browser fetch() from other origins works for simple GET (no custom auth). Prefer cache: 'no-store' so portals pick up board refreshes. The site service worker already treats .json as live (no-store).

Example

fetch('https://nirajbhusal.github.io/rasuwa-flood-bulletin/api/overview.json', {
  cache: 'no-store'
})
  .then(r => r.json())
  .then(data => {
    // data.cards[0].value → deaths, etc.
    // Always show data.credit[lang] + link to data.links.overview
    console.log(data.as_of.en, data.cards.map(c => [c.id, c.value]));
  });
# curl
curl -sS 'https://nirajbhusal.github.io/rasuwa-flood-bulletin/api/overview.json' | head

Schema notes

  • Eight cards in homepage order: dead, injured, miss, rescued, police, tunnel, deploy, comms.
  • Do not re-sum labeled splits (especially missing / holding).
  • Nepal Police card is a separate source from NDRRMA hero KPIs.
  • Name-list rescue count on the names page is not the homepage rescued total.
  • comms.value is null (composite lead 117 · 76); use value_display.
  • Please keep credit / attribution_html visible when republishing figures.

Process note · अद्यावधिक

When the NDRRMA board (or labeled Nepal Police board) updates, refresh api/overview.json alongside the homepage #overview KPI cards — same numbers, same as-of stamp. Do not invent figures.
